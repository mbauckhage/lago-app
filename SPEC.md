# Lago Nostre product spec

## Current state

The app is called Lago Nostre. It uses the Abendsee palette with deep lake-blue surfaces, a text-only wordmark and a Swiss Standard German interface. Warm coral highlights primary actions and selected replies. Lighter lake-blue accents mark pending invitations, avatar initials and active navigation. Members register with an email, password and display name and wait for administrator approval. Approved members can post, edit and cancel events, invite people or groups, view guest responses, RSVP, and browse the monthly calendar. Administrators approve accounts and manage both groups. Members can update their profile and subscribe to a revocable private calendar URL.

New events use Europe/Zurich time. The feed shows newest posts first. Group invitations follow current membership and preserve a member’s last RSVP if they regain access. Cancelled events stay visible in Lago and are removed from the personal subscription. Profile notification preferences default to on. Push delivery supports invitations, event edits and cancellations on subscribed devices; email delivery remains planned.

## Product requirements

**Goal.** Give the Lago friends group a private, mobile-first app to make plans, see who’s coming, and keep personal calendars up to date.

- **Registration and approval.** Anyone can register with email and password on Lago’s own login page, then set their display name. New accounts see a pending approval screen. Only accounts approved by the administrator can use the app. The display name is the member’s sole public name.
- **Profile and notifications.** Members can update their display name and profile photo. Email and push preferences are on by default and can be turned off independently. On the first opening for an approved member with push enabled, Lago requests browser permission as soon as the account is known, without waiting for the feed, opening animation, or push setup. Browsers requiring a user gesture (including iOS) show a visible activation button immediately, even during the opening animation. Dismissing that prompt or denying permission prevents repeated first-opening requests for that account in the same browser; Settings keeps manual device controls. After sign-in, a previously activated device restores its subscription when browser permission is still granted. Push requires HTTPS, browser permission and, on iOS/iPadOS 16.4+, installation and launch from the Home Screen. Denied or unsupported devices show instructions. Turning off the saved push preference silences all devices; disabling a device removes its subscription. Signing out disconnects that device. Notifications open the relevant event after sign-in. Delivery is queued with bounded retries and expired subscriptions are removed. **Planned:** email delivery.
- **Create an event.** The host enters a title, date and time, with optional location, notes and a cover photo. They can invite approved individuals and any combination of their own groups. The editor shows only their current groups. Editing an older event preserves existing invitations to groups the host has since left. Each person gets one invitation.
- **Group membership.** The administrator manages both groups. Changes apply automatically to already-posted events that invite the group. Newly added members gain access and see those events in their feed and Lago calendar. Removed members lose access and the events disappear from both views unless they’re also invited directly or through the other group.
- **Feed and RSVP.** Lago opens to a feed of events you’re invited to or hosting. Open sessions refresh the feed, event details and Lago calendar when a visible event, RSVP or access changes, and catch up on reconnection or resume. An open session announces newly received invitations in the app. Invitees can choose or change **Going**, **Maybe** or **Declined**. Unanswered invitations show all three response buttons in neutral blue-grey, with none selected, in both the feed and event details. Only the saved response is highlighted. The host and all invitees can see the guest list and current responses.
- **Edits and cancellations.** Hosts can edit or cancel their events. The feed shows updated details or marks the event as cancelled. Notify current invited guests of edits and cancellations by push according to their saved settings and device subscriptions. **Planned:** email notifications.
- **Calendars.** Lago’s monthly view includes hosted events and all invitations, including declined ones. Members can subscribe to a private personal calendar link. The subscription includes hosted events and invitations marked **Going** or **Maybe**. Edits update entries. Cancellations, declines and loss of invitation access remove them when the personal calendar app next refreshes.

**Platform.** Mobile-first web app with home-screen installation on supported browsers. The app uses Vue with Vite, Fastify and PostgreSQL. Railway is configured with separate test and production environments, each with its own database.

On mobile, the page stays at its initial scale: pinch and double-tap gestures do not zoom the whole interface. Horizontal and vertical touch scrolling remain available.

The home-screen icon and browser favicon use the classic Lago wordmark in warm coral (#F29B85) on deep lake blue (#233F50). Home-screen installation uses the PNG icons in the web app manifest or the Apple touch icon on iOS. In Railway’s test environment, the home-screen icon and browser favicon add a larger, tilted “Test” label above the wordmark.

A fresh tab or standalone app session plays the transparent lakeside GIF once on the same deep lake-blue background (#233F50) as the app while account data loads. The opening can be skipped as soon as the app is ready. Reloading or resuming the same session skips the intro. Slow startup loads can show the same GIF while waiting. Event notification links go straight to the requested event when ready, and reduced-motion users see a text loading state.

The header displays the lakeside GIF as a decorative backdrop at 30% opacity behind the title and event button. The GIF holds its final frame for an extra five seconds between loops. The backdrop is hidden when reduced motion is requested. The header reserves the device’s top safe area in addition to its 80px base height and padding. Installed standalone apps add another 16px of top clearance so the title and actions sit below the iOS system status-bar blur. The clearance stays within the app viewport, preserving the bottom navigation and scrollable content area.

## Local development

`./start.sh` starts the checkout’s local PostgreSQL database when present, using its matching major version from `PATH` or a standard Homebrew installation. It reports a missing matching version or displays the database log on startup failure. The database stays running when the API and frontend stop.

## Frontend implementation

Clicking a host’s name or avatar on an event card, or a host or guest name in event details, opens a full-page member profile with a back button at the top left. «Eigene Termine» shows events hosted by that member; «Alle Termine» also includes their invitations (including declined and unanswered invitations). Both tabs use a three-column grid, including on mobile, with compact tiles that open event details. Profiles only show events the viewing member can already access. Back restores the previous view and scroll position, including event details when opened from there. The main Profile navigation tab shows the signed-in member using the same profile component and event tabs. It has no back button and has an «Einstellungen» button at the top right. Settings opens the former Profile page with profile editing, notification preferences and device controls, personal calendar, administration and sign-out; its back button returns to the own profile. Selecting Profile in the main navigation also returns to the own profile.


In Settings, «In Kalender-App öffnen» opens the member’s private subscription URL using the `webcal://` scheme so compatible devices can hand it to their calendar app for subscription confirmation. The link always uses the current calendar token, including after a reset. Devices without a compatible handler can still copy the HTTPS link and add it manually. Opening the link does not confirm that a subscription was created.

In Settings, clicking the profile photo (or initials when no photo is saved) directly opens the device’s image picker. The picker has no visible upload label or native file-input text; the photo button is keyboard accessible and labelled «Profilfoto ändern». Profile photos have an inline circular crop preview. Members can choose a new image or edit their saved photo, adjust zoom and horizontal/vertical position, and cancel their changes. Saving the profile stores the selected square crop (up to 512 × 512 pixels); avatars display it as a circle. Removing a photo restores initials. Invalid images block saving until replaced or cancelled.

The event editor’s title image field uses a full-width dotted-outline image selector with a centred image icon. Clicking it or activating its file input with the keyboard opens the image picker. Selected images appear as a preview with an option to choose another image; existing covers are previewed when editing.

Event covers and profile photos accept JPEG, PNG and WebP files. Before saving, the browser converts files larger than 1 MiB to WebP, reducing the longest edge to at most 1920 pixels, then lowering quality and dimensions until the result fits within 1 MiB. Browsers without WebP encoding use PNG and reduce dimensions instead. Smaller files remain unchanged. Aspect ratio and transparency are preserved. Unreadable or unconvertible images show an error without saving the form; the server continues enforcing its image payload limit.

The Vue interface uses Tailwind CSS through its Vite plugin, with shared theme tokens and reusable UI components for buttons, navigation tabs, avatars and form fields. Event cards and RSVP controls compose these primitives. This structural refactor preserves the layout, Swiss German copy, responsive sheets and existing product behavior.

## Push operations

Web Push VAPID keys are generated once and stored in PostgreSQL, independently in each environment. Preserve `push_config` across deploys to keep existing device subscriptions valid. Set `WEB_PUSH_SUBJECT` to a monitored `mailto:` contact (default `mailto:admin@lagonostre.ch`). Creating an event queues one notification per distinct invitee and one for the host. Delivery starts after commit, with a five-second queue sweep for recovery. Delivery is best effort; temporary failures retry up to four times and may produce duplicates on devices that already received a multi-device delivery. Group membership changes update access but do not send push notifications.

## Home Screen installation

Approved mobile browser users receive an installation invitation after the main feed and opening animation have loaded, following eight seconds without interaction. It waits while the app is busy, a dialog or notification activation is open, an input is focused, or the page is hidden. It never opens automatically on desktop, in standalone apps or detected embedded browsers. Settings always keeps «Zum Startbildschirm hinzufügen» available, including after two dismissals.

The invitation uses a dimmed native dialog, centred on desktop and a rounded bottom sheet with a decorative handle on mobile. It shows the app icon, «Jetzt als App», a short benefit, and full-width primary and «Später» actions. The primary action invokes a captured native install prompt, or «So geht’s» switches to the manual guide in place. Native rejection counts as dismissal. X, backdrop, Escape, «Später» and guide completion each dismiss the current offer once. Dismissals are stored per browser: the next automatic offer waits 30 days; after two dismissals automatic offers stop. Settings visits do not reset or increment this count. Storage restrictions retain the policy for the current session.

Manual guides show three icon rows: iOS/iPadOS «Teilen», «Zum Home-Bildschirm», «Hinzufügen»; Android «Browsermenü», «App installieren» or «Zum Startbildschirm hinzufügen», then confirmation. Browser labels are bold. Embedded browsers first explain opening in Safari or Chrome. Guides remind users to launch the new Home Screen icon and end with «Verstanden». Desktop offers native installation when available, otherwise a short note pointing to mobile options. Installed users opening Settings see confirmation. Dialog focus stays trapped and returns to its trigger (or the feed heading for an automatic offer). Confirmed installation closes the dialog and persists suppression of automatic offers in this browser; accepting a native prompt alone does not claim confirmation.
